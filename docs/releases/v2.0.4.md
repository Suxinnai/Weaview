# Weaview v2.0.4 / 织境 v2.0.4

## 中文

v2.0.4 把「说出口就能生效」贯彻到底：外观指令不再需要一次模型往返，生图上限也从 4 张放宽到 6 张。同时清理了会话恢复、角色分配和主题命令标记这些容易被忽视的边界行为。

### 生图体验

- 单次生图数量上限从 4 张提升到 6 张；数量限制统一收敛为共享常量，网关、Gemini、OpenAI 图像与原生图像 Provider 全部一致。
- 图像模式发送按钮文案改为「织梦」；计数条带展开时带淡入上滑动画，收起的间距与圆角也重新校准。

### 聊天外观指令

- 直接输入外观指令（如「换成紫色背景」「改回默认主题」）现在本地即时生效，不再等待模型往返，也不消耗任何模型额度。
- 完成后用一句诗意的自然语言确认，例如「背景已经换成一层清浅雾色，像雨后的晨光一样安静」；模型不再需要输出 JSON 命令。
- 未指明颜色时按情绪提供默认背景：夜晚与星空对应深色，暖色与奶油对应米色，紫色与薰衣草对应淡紫，蓝色、雨雾与天空对应天蓝。
- 从模型回复中剥离完整或残缺的 `<modify_ui_state>` 标记，主题命令永远不会泄漏到可见消息。
- 消息正文支持按外观 mood 切换斜体字重。

### 角色分配与会话恢复

- 纯生图模型不再被分配到主对话、标题、建议或翻译角色，避免图像模型被误用为文本模型。
- 启动时只恢复上次明确选择的会话；移除此前「找不到就退回最近更新会话」的兜底逻辑，恢复行为变得可预期。

### 导航与图片预览

- 从屏幕左边缘向右滑动即可打开侧边栏，新增 28 像素宽的边缘手势区域，不干扰消息列表滚动。
- 全屏图片预览重构：玻璃质感顶栏（返回、下载、更多）、底部缩略图导轨、逐张保存与操作，并补充无障碍语义标签。

### 设置打磨

- 提供商模型网格、多模型对比选择器与模型下拉的间距、圆角与高度细节继续收紧。
- 移除「暂无提供商」占位卡片，设置页结构更干净。

### 质量验证

- Flutter 静态分析无问题。
- 完整自动化测试套件全部通过。
- 已在 Android API 35 模拟器上启动并验证主界面渲染。
- 发布 APK 使用与 v2.0.3 相同的签名证书，已验证可覆盖升级。

### 维护者吐槽

「生成 4 张」变成「织梦」之后，按钮终于不再像一张价目表。至于外观指令，模型本来就不该为了换个背景写一屏 JSON——现在你开口，它立刻照办，只用一句话回你。

### 下载

绝大多数 Android 手机请选择 `arm64-v8a`。较老的 32 位设备使用 `armeabi-v7a`；模拟器或少数兼容设备使用 `x86_64`。

> 兼容性提醒：本版本要求 Android 7.0 或更高版本。HTTP Base URL 可以使用，但连接内容不会被传输层加密。

## English

v2.0.4 makes "say it, see it" real: appearance requests no longer need a model round trip, and the image limit rises from 4 to 6. It also cleans up the edge behaviors people rarely notice but always feel: session resume, role assignment, and theme-command markup.

### Image generation

- Raised the per-request image generation limit from 4 to 6, centralized in a shared constant used consistently by the gateway, Gemini, OpenAI, and native image providers.
- The image-mode send button is now labeled Weave Dream, and the count strip animates in with a fade and slide.

### Chat appearance commands

- Direct appearance requests such as "make the background purple" or "restore the default theme" apply instantly on device with no model round trip and no token cost.
- Completion is confirmed with a short poetic sentence such as "The background has shifted to a pale mist, quiet like morning light after rain"; models no longer need to emit JSON commands.
- When no color is named, mood picks the default: dark for night and starry scenes, cream for warm tones, lavender for purple themes, and sky blue for rain, fog, and skies.
- Complete and unfinished `<modify_ui_state>` markup is stripped from assistant replies, so theme commands never leak into visible messages.
- Message text can follow the appearance mood with an italic weight.

### Role assignment and session resume

- Image-generation-only models can no longer be assigned to primary chat, title, suggestion, or translation roles, preventing image models from being misused as text models.
- Startup now resumes exactly the previously selected session; the fallback that silently switched to the most recently updated session is gone.

### Navigation and image preview

- Swiping right from the left screen edge opens the sidebar via a new 28-pixel gesture zone that never blocks message scrolling.
- The fullscreen image preview was rebuilt with a glass top rail (back, download, more), a bottom thumbnail rail, per-image saving and actions, and accessibility semantics.

### Settings polish

- Tighter spacing, radii, and heights across provider model grids, the model comparison picker, and model dropdowns.
- Removed the empty-provider placeholder card so the settings page stays clean.

### Quality verification

- Flutter static analysis passes with no issues.
- The complete automated test suite passes.
- Verified the main screen renders on an Android API 35 emulator.
- Release APKs use the same signing certificate as v2.0.3 and were verified for in-place upgrades.

### Maintainer's grumble

"Generate 4 images" becoming "Weave Dream" finally makes the button feel like part of the app instead of a price list. And for appearance tweaks, a model should never write a screen of JSON just to change a background — now you say it, it happens, and it answers in one sentence.

### Downloads

Most Android phones should use `arm64-v8a`. Choose `armeabi-v7a` for older 32-bit devices and `x86_64` for compatible emulators or uncommon devices.

> Compatibility note: Android 7.0 or newer is required. HTTP Base URLs are supported, but their traffic is not encrypted at the transport layer.
